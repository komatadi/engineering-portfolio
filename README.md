## How I work

My normal pattern is:

```text
Business / user problem
        ↓
Capability & architecture framing
        ↓
Boundaries, contracts and key decisions
        ↓
Prototype / implementation slice
        ↓
Test, observe and challenge assumptions
        ↓
Engineering guardrails & operational model
        ↓
Scale through teams and reusable platforms
```

I use coding agents and AI development tools extensively. I treat them as engineering accelerators, not as substitutes for technical ownership. I remain accountable for the problem framing, architecture, security boundaries, interfaces, acceptance criteria, reviews, verification and trade-offs.

## What is intentionally not published

The implementation repositories behind these case studies remain private. This portfolio intentionally excludes:

- production source code;
- credentials, API keys, environment values or infrastructure secrets;
- private datasets and personal information;
- proprietary names or identifiers where public usage is not appropriate; and
- implementation details that would unnecessarily expose reusable IP.

The purpose is to demonstrate **technical reasoning and engineering depth**, not to distribute private code.
